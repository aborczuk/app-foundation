# HUD: T005 - Restrict scoped code queries so irrelevant markdown retrieval is skipped in `scripts/read_code.py`

## Objective

Deliver `T005` so scoped code queries stop paying for irrelevant markdown retrieval by default.

This task is the retrieval-side counterpart to the scoped routing work: it narrows semantic candidate collection for code-scoped requests without regressing broad or markdown-oriented discovery.

## Relevant Domains

- `Code Reading and Discovery`: this task changes the candidate collection path inside semantic anchor resolution.
- `Reuse at Every Scale`: it should reuse the routed request-scope and content-type signals rather than inventing new heuristics.
- `Resilience`: broad and markdown-focused requests must keep the richer retrieval path after this scoped optimization lands.

## Candidate Design Slices

- `Slice PL-01 - Scoped Trust Fast Path` — skip markdown retrieval when it is irrelevant for scoped code queries while preserving seam selection. Primary seam: `scripts/read_code.py:_query_semantic_anchor_candidate`.
- `Slice PL-02 - Broad Discovery and Conditional Escalation` — preserve markdown-aware behavior questions for broad queries. Supporting seam: `scripts/read_code.py:_resolve_pattern_anchor`.

## Proposed Solution

- Update `_query_semantic_anchor_candidate(...)` so scoped code requests can avoid the unconditional markdown candidate query.
- Base the decision on the routed scope signal and existing content-type/path information rather than a raw string heuristic inside the retrieval helper.
- Preserve the existing merged ranking path for broad or markdown-capable requests so broad discovery still considers both scopes when appropriate.
- Change the following symbols in this task: `scripts/read_code.py:_query_semantic_anchor_candidate` and any immediate helper that decides candidate scopes.

## Current Repo Behavior

- `_query_semantic_anchor_candidate(...)` currently always calls `_vector_find_candidates(..., "code")` and `_vector_find_candidates(..., "markdown")` before filtering by content type.
- The merged candidate set is sorted by `_vector_anchor_rank` after both code and markdown queries have already run.
- For scoped code-symbol reads, the markdown branch can return nothing while still incurring measurable latency.

## Target Behavior

- Scoped code queries skip markdown candidate retrieval when the routed request class makes markdown irrelevant.
- Broad and markdown-oriented queries still preserve the mixed candidate path when that is part of the intended behavior.
- The task fulfills `Slice PL-01` without weakening the broad discovery contract that `T009` and `T010` will refine later.
