# HUD: T009 - Rework broad-query routing so healthy-session trust can satisfy normal discovery reads in `scripts/read_code.py` and `scripts/read_code_health.py`

## Objective

Deliver `T009` so normal broad discovery reads can rely on healthy-session trust instead of paying the heavyweight path every time.

This task implements the broad-read routing contract without removing markdown-aware discovery.

## Relevant Domains

- `Code Reading and Discovery`: this task changes the routing for broad natural-language discovery.
- `Resilience`: the broad path must still escalate when results are weak, empty, stale, or ambiguous.
- `Reuse at Every Scale`: it should consume the same query-scope and trust contracts created earlier rather than creating a separate broad pipeline.

## Candidate Design Slices

- `Slice PL-02 - Broad Discovery and Conditional Escalation` — use session-level trust for healthy broad reads while preserving markdown-aware behavior. Primary seams: `scripts/read_code.py:_resolve_pattern_anchor` and `scripts/read_code_health.py:_refresh_indexes_for_read`.

## Proposed Solution

- Update the broad-query branch around `_resolve_pattern_anchor(...)` so healthy-session trust can satisfy ordinary broad discovery reads without forcing the slowest recovery path by default.
- Preserve the mixed code-plus-markdown candidate behavior for broad requests.
- Route only stale, empty, weak, or conflicting outcomes toward the heavier trust or recovery path.
- Change the following symbols in this task: `scripts/read_code.py:_resolve_pattern_anchor`, `scripts/read_code.py:read_code_context`, and the broad-read branch of the trust contract in `scripts/read_code_health.py`.

## Current Repo Behavior

- Broad and scoped requests currently share the same preflight and anchor-resolution entrypoint.
- `_resolve_pattern_anchor(...)` always begins with the current semantic candidate path, and the surrounding preflight work does not distinguish broad requests that are already safe to satisfy from session trust.
- The broad path therefore inherits more heavyweight freshness work than necessary even when a healthy session is already available.

## Target Behavior

- Broad discovery requests can use session-level trust in the healthy case.
- Broad requests still keep mixed code-plus-markdown discovery.
- The task fulfills `Slice PL-02` by moving heavyweight trust work to the exceptional cases instead of the default path.
