# HUD: T015 - De-prioritize test-file candidates in regular context discovery unless the request explicitly targets tests in `scripts/read_code.py` and `tests/unit/test_read_code_shortlist.py`

## Objective

Deliver `T015` so ordinary `read_code context` discovery stops surfacing test files ahead of implementation files when the user is asking a regular code-understanding question.

This task preserves test visibility for explicitly test-targeted requests while making default discovery ranking more useful.

## Relevant Domains

- `Code Reading and Discovery`: this task changes candidate ranking for regular context search.
- `Testing`: tests must remain discoverable when the request explicitly targets them.
- `Performance`: the change should stay in ranking logic, not widen the retrieval path.

## Candidate Design Slices

- `Slice PL-02 - Broad Discovery and Conditional Escalation` — preserve markdown-aware broad discovery while improving default candidate ordering for implementation-versus-test results. Primary seam: `scripts/read_code.py:_vector_anchor_rank`.

## Proposed Solution

- Add a narrow ranking adjustment in `scripts/read_code.py` so candidates from test files are down-ranked during ordinary context discovery.
- Preserve test-first behavior when the request explicitly targets tests, such as a test-scoped path or a clearly test-oriented query.
- Keep the change local to candidate ranking and request-shape interpretation; do not widen this task into freshness or fallback work.
- Change the following symbols in this task: `scripts/read_code.py:_vector_anchor_rank` and any immediate helper needed to detect explicit test targeting.
