# HUD: T012 - Implement explicit trust invalidation and escalation-state signaling in `scripts/read_code_health.py` and `scripts/read_code.py`

## Objective

Deliver `T012` so trust invalidation and escalation state are explicit enough for maintainers to tell when the fast path was reused and when recovery logic was necessary.

This is the implementation half of User Story 3.

## Relevant Domains

- `Resilience`: this task makes trust invalidation and escalation-state signaling explicit and reviewable.
- `Code Reading and Discovery`: the read-preflight system must expose when it is trusting cached state versus escalating.
- `Human-First Decisions`: maintainers need clear signals when the fast path was used or bypassed.

## Candidate Design Slices

- `Slice PL-02 - Broad Discovery and Conditional Escalation` — make escalation state explicit for the exceptional path.
- `Slice PL-03 - Benchmark and Regression Coverage` — keep the signaling measurable and testable. Primary seams: `scripts/read_code_health.py:vector_index_probe` and `scripts/read_code.py` runtime-note or fallback notice handling.

## Proposed Solution

- Extend the trust and probe path so invalidation conditions and escalation-state transitions are explicit in the health contract.
- Use `vector_index_probe(...)` and related runtime-note machinery to surface whether the current read reused trusted state, observed staleness, or escalated to refresh or recovery.
- Thread the resulting state into the existing warning or note mechanisms without changing the primary compact result payload.
- Change the following symbols in this task: `scripts/read_code_health.py:vector_index_probe`, the trust helper introduced in `T002`, and the runtime-note/notice handling consumed by `read_code.py`.

## Current Repo Behavior

- `vector_index_probe(...)` returns a parsed freshness payload with `status`, `stale_reason`, `stale_drift_paths`, and signal metadata.
- `_refresh_indexes_for_read(...)` consumes `_consume_vector_runtime_note()` only on failure and prints a generic preflight error message.
- Escalation and trust reuse are not yet exposed as a first-class, explicit state contract for later callers or maintainers.

## Target Behavior

- Trust invalidation and escalation state are explicit and deterministic.
- The fast path remains observable without polluting the primary compact result output.
- The task fulfills User Story 3 by making maintainers able to tell when the fast path was reused and when recovery was necessary.
