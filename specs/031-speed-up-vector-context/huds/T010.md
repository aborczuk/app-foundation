# HUD: T010 - Make broad fallback and recovery conditional on empty, weak, stale, or conflicting outcomes in `scripts/read_code.py`

## Objective

Deliver `T010` so broad fallback and recovery work only runs when the broad-read outcome is empty, weak, stale, or conflicting.

This task defines the exceptional-case policy for User Story 2.

## Relevant Domains

- `Code Reading and Discovery`: this task changes when fallback discovery is allowed to run.
- `Resilience`: the fallback trigger policy must stay safe and observable.
- `Simplicity First`: keep fallback conditional on a small, explicit set of bad outcomes instead of letting it remain the default.

## Candidate Design Slices

- `Slice PL-02 - Broad Discovery and Conditional Escalation` — make heavyweight freshness and fallback work conditional on stale, empty, weak, or ambiguous outcomes. Primary seam: `scripts/read_code.py:_resolve_pattern_anchor`.

## Proposed Solution

- Refactor the broad resolution flow so fallback and recovery paths are gated by explicit outcome checks: empty candidates, low-confidence or weak results, stale trust state, or conflicting candidate signals.
- Preserve the direct return path for broad reads that already have a satisfactory result.
- Keep the fallback notice and recovery hooks observable so `T012` can later expose the escalation state clearly.
- Change the following symbols in this task: `scripts/read_code.py:_resolve_pattern_anchor` and any immediate helper that decides whether a broad resolution outcome is good enough.

## Current Repo Behavior

- `_resolve_pattern_anchor(...)` currently has one fallback branch for the no-match case when `vector_match` is `None` and a file path is available.
- The function refreshes candidates after `codegraph_discover_or_fail(...)` and then proceeds with the refreshed result if one appears.
- The fallback trigger is still narrower and less explicit than the feature's desired policy around weak, stale, or conflicting outcomes.

## Target Behavior

- Broad fallback and recovery work run only for explicitly bad outcomes.
- Satisfactory broad results return directly without unnecessary escalation.
- The task fulfills `Slice PL-02` by turning the fallback policy into an explicit, reviewable branch instead of an implicit default.
