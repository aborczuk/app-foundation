# HUD: T003 - Wire the new query-scope and trust helpers into the existing preflight contract in `scripts/read_code.py` and `scripts/read_code_health.py`

## Objective

Deliver `T003` so the new query-scope classification and trust-evaluation helpers actually drive the existing `read_code context` preflight and anchor-resolution contract.

This task is the wiring point between the `read_code.py` and `read_code_health.py` changes introduced in `T001` and `T002`.

## Relevant Domains

- `Code Reading and Discovery`: this task changes the control flow that connects parsed request shape, read preflight, and anchor resolution.
- `Reuse at Every Scale`: the goal is to thread the new helpers into the current contract instead of creating parallel scoped and broad entrypoints.
- `Resilience`: the wired path must preserve the existing failure surface while routing scoped and broad requests differently.

## Candidate Design Slices

- `Slice PL-01 - Scoped Trust Fast Path` — use the scope decision to drive preflight and keep scoped requests on the fast path. Primary seams: `scripts/read_code.py:read_code_context` and `scripts/read_code_health.py:_refresh_indexes_for_read`.
- `Slice PL-02 - Broad Discovery and Conditional Escalation` — ensure broad requests still reach the heavier path when needed instead of inheriting the scoped fast path accidentally. Supporting seam: `scripts/read_code.py:_resolve_pattern_anchor`.

## Proposed Solution

- Extend the local `read_code context` flow so the scope classification from `T001` is passed into the preflight contract from `T002`.
- Update `_refresh_indexes_for_read(...)` and the immediate call sites so they accept the new scope signal instead of inferring broad-versus-scoped behavior internally.
- Thread the same signal into `_resolve_pattern_anchor(...)` or its immediate surrounding contract so later tasks can branch retrieval and fallback behavior without reclassifying the request.
- Change the following symbols in this task: `scripts/read_code.py:read_code_context`, `scripts/read_code.py:_resolve_pattern_anchor`, and `scripts/read_code_health.py:_refresh_indexes_for_read` call sites.

## Current Repo Behavior

- `read_code_context` currently calls `_refresh_indexes_for_read(preflight_path, verbose=verbose)` with only a file path and verbosity flag.
- `_resolve_pattern_anchor(...)` is called with pattern, normalized pattern, and candidate/fallback flags, but no explicit query-scope signal.
- The current contract therefore has no shared routing value connecting parsed request shape to preflight or retrieval behavior.

## Target Behavior

- The context flow carries one explicit scope decision from argument parsing through preflight and into anchor resolution.
- Scoped and broad behavior continue to share the same top-level command surface, but downstream helpers no longer need to guess the request class independently.
- The task fulfills `Slice PL-01` and prepares `Slice PL-02` by making the routing signal explicit and reusable.
