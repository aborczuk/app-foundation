## Objective

Deliver `T006` so the task scope satisfies: Add a dedicated local Tetris runtime path in `src/clickup_control_plane/app.py`, `src/clickup_control_plane/config.py`, and supporting dev-runner/docs seams so `/tetris` can be started and manually verified without requiring ClickUp/n8n control-plane bootstrap configuration..

## Relevant Domains

- Runtime Surface: the Tetris route should be locally runnable without forcing unrelated control-plane clients to boot.
- Developer Experience: manual verification should use a short, reliable local run path instead of heavyweight dummy env setup.
- Configuration Boundaries: control-plane env parsing and app bootstrap need a narrower seam so Tetris runtime checks stop depending on ClickUp/n8n configuration.

## Candidate Design Slices

- PL-01 - Tetris Runtime Surface: refine the FastAPI hosting seam so the isolated Tetris route can be launched and verified without perturbing unrelated control-plane startup.
- PL-03 - Playable Browser Shell: preserve the playable browser shell while making manual verification practical for local development.

## Proposed Solution

- Split or gate the shared bootstrap path around `src/clickup_control_plane/app.py:_lifespan` so a dedicated local Tetris runtime path can mount `/tetris` without eagerly constructing ClickUp/n8n control-plane clients.
- Update the runtime/config contract in `src/clickup_control_plane/config.py` and the feature quickstart/dev-runner instructions so the lightweight Tetris run path is explicit, documented, and testable.

## Current Repo Behavior

The shared FastAPI lifespan in `src/clickup_control_plane/app.py:_lifespan` boots control-plane state, dispatch, ClickUp, and reconciliation services before any route is available. As a result, local `/tetris` verification currently requires dummy `CLICKUP_API_TOKEN`, `CLICKUP_WEBHOOK_SECRET`, `N8N_DISPATCH_BASE_URL`, and JSON `CONTROL_PLANE_ALLOWLIST` values even though the Tetris route itself does not need those integrations for manual play checks.

## Target Behavior

- Preserve the playable Tetris surface and server-backed session flow already established for US1.
- Keep the US1 independent test practical: a human should be able to start the Tetris runtime locally and manually verify the board, controls, and gravity loop without unrelated control-plane secrets or network clients.
- Satisfy PL-01 by keeping the Tetris runtime seam isolated from existing `/control-plane/*` behavior even during local startup.
- The bootstrap seam at `src/clickup_control_plane/app.py:_lifespan` should expose a dedicated local Tetris path or lazy control-plane initialization branch that leaves `/tetris` usable while skipping unnecessary ClickUp/n8n bootstrap for that mode.
