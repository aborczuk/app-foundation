# HUD: T015 - Typed workflow outcomes

## Objective

Deliver `T015` so the task scope satisfies: Add validator outcome models in scripts/speckit_workflow_outcomes.py for pass, recoverable retry, human pause, transient dependency failure, terminal machine failure, and completed states..

## Relevant Domains

- resilience: stable classifications determine retry, pause, or terminal behavior.
- ops governance: reason/evidence/attempt fields make decisions auditable.
- observability: one typed result enables bounded diagnostics and rehydration.

## Candidate Design Slices

- **PL-04 — Implement Pre-Implementation Phase Workflow Adapters.** Define the shared deterministic outcome model used by adapters, loops, and human policy.

## Proposed Solution

- Create `scripts/speckit_workflow_outcomes.py` with immutable `ValidationOutcome` and enum/status definitions for pass, recoverable retry, human pause, transient dependency failure, terminal machine failure, and completed.
- Require reason code, recoverability, human reason when applicable, attempt, evidence pointer, diagnostic pointer, and permitted next action.
- Add constructors/validation that reject inconsistent combinations, such as pass with pause reason or human pause without authority input.

## Current Repo Behavior

`scripts/pipeline_driver.py:_runtime_failure_result` and `emit_human_status` provide separate result shapes; there is no shared typed outcome contract across workflow adapters.

## Target Behavior

- Preserve FR-009 and FR-016: deterministic gates produce complete structured outcomes, not booleans or generic exits.
- Specialize PL-04 by giving T013c/T014 one typed result vocabulary.
- Completed is distinct from pass; no type permits implicit success after an error.
