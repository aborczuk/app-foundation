# HUD: T006 - Manifest lifecycle validation

## Objective

Deliver `T006` so the task scope satisfies: Update manifest validation in scripts/validate_command_manifest.py to reject legacy or ambiguous routes for canonical pre-implementation phases..

## Relevant Domains

- ops governance: validation makes manifest ownership enforceable.
- build pipeline: rejects invalid lifecycle data before routes execute.
- testing: error reasons must be deterministic and covered by T007.

## Candidate Design Slices

- **PL-02 — Define Workflow Ownership and Manifest Routing.** Validate the canonical manifest contract introduced by T005.

## Proposed Solution

- Extend `scripts/pipeline_ledger.py:cmd_validate_manifest` and its parsing helpers to require the new lifecycle fields for canonical pre-implementation routes.
- Reject missing owner/adapter/validator/event/provenance fields, conflicting owners, inconsistent mirror versions, legacy routes that bypass canonical mapping, and terminal routes that authorize implementation start.
- Return bounded machine-readable reasons naming the affected manifest key and one non-mutating correction action.

## Current Repo Behavior

Repository manifest validation is implemented by `scripts/pipeline_ledger.py:cmd_validate_manifest`; `scripts/validate_command_manifest.py` does not exist. Existing validation therefore needs extension at the real command boundary.

## Target Behavior

- Preserve FR-028 and FR-029: manifest/mirrors have one validated ownership source and direct reruns cannot bypass phase gates.
- Specialize PL-02 by making ambiguous or legacy lifecycle routes a deterministic hard failure.
- Validation must reject implementation-start capability in the pre-implementation terminal route.
