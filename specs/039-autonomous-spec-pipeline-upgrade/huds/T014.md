# HUD: T014 - Specify phase success gate

## Objective

Deliver `T014` so the task scope satisfies: Wire specify-phase generation so scripts/speckit_specify_step.py cannot emit success after scaffold-only or failed fill..

## Relevant Domains

- resilience: scaffold-only or failed fill must not advance a phase.
- ops governance: success request is gated by deterministic artifact validation.
- testing: both bootstrap and fill modes need explicit outcome assertions.

## Candidate Design Slices

- **PL-04 — Implement Pre-Implementation Phase Workflow Adapters.** Apply the adapter success rule to the existing specify workflow.

## Proposed Solution

- Modify `scripts/speckit_specify_step.py:_run_step_mode` to use the T013 contract/outcome boundary after generation.
- Distinguish bootstrap-only scaffold from completed fill; require expected spec artifact, non-template content, phase validation, and typed pass outcome before returning a `specify_completed` event request.
- Return recoverable, human, transient, or terminal outcome with diagnostics for failed fill/validation; never append the event directly.

## Current Repo Behavior

`scripts/speckit_specify_step.py:_run_bootstrap_only_mode` and `_run_step_mode` are separate modes. The existing flow scaffolds/specifies but lacks the new unified phase-contract gate against scaffold-only success.

- Preserve FR-006, FR-007, and US1: `orchestrate -> extract -> scaffold -> LLM Action -> validate -> emit/handoff` is complete before success.
- Bootstrap-only state cannot emit phase success.
- Failed generated output is classified and diagnostic, not silently advanced.
