# HUD: T013c - Phase adapter execution boundary

## Objective

Deliver `T013c` so the task scope satisfies: Implement the phase-adapter execution boundary in scripts/speckit_workflow_adapter.py so it invokes the declared runner and validator, exposes declared diagnostics, and permits success-event or handoff requests only after a valid contract outcome..

## Relevant Domains

- resilience: deterministic validator outcome owns success.
- ops governance: event/handoff requests occur only after valid phase completion.
- observability: expose declared diagnostics and result artifacts.

## Candidate Design Slices

- **PL-04 — Implement Pre-Implementation Phase Workflow Adapters.** Execute resolved contracts without allowing scaffold-only or failed outputs to advance.

## Proposed Solution

- Implement `scripts/speckit_workflow_adapter.py:execute_phase_contract` using a T013b resolved contract.
- Invoke the declared runner inside its mutation/effect scope, collect its artifact/result, invoke the declared validator, and normalize the typed outcome.
- Return a success-event or handoff request only for validator pass; recoverable/human/transient/terminal outcomes return diagnostics and no success event.

## Current Repo Behavior

`scripts/pipeline_driver.py:append_pipeline_success_event` exists, but no adapter currently proves phase-specific validation before an event/handoff request.

## Target Behavior

- Preserve FR-007, FR-008, FR-009, and FR-015: validated artifact completion is the only phase-success condition.
- Specialize PL-04 by treating scaffold-only, absent, or failed generated artifacts as non-success.
- Event request remains a request envelope; ledger append authority stays downstream.
