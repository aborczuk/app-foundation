# HUD: T005 - Manifest workflow ownership routing

## Objective

Deliver `T005` so the task scope satisfies: Extend command-manifest.yaml with workflow step ownership, permission class, result artifact, validator, event, provenance, and pre-implementation terminal route fields for the autonomous pipeline..

## Relevant Domains

- build pipeline: manifest becomes the reproducible ownership source for all pre-implementation routes.
- ops governance: declares permission, event, validation, and provenance policy.
- security: command permissions and side-effect scopes must be explicit.

## Candidate Design Slices

- **PL-02 — Define Workflow Ownership and Manifest Routing.** T005 establishes the canonical data contract that later adapters and validators consume.

## Proposed Solution

- Extend `command-manifest.yaml` with a versioned pre-implementation workflow schema per canonical phase: owner, route, workflow step, adapter, timeout, permission class, mutation scope, result artifact, validator, success event, version, and provenance.
- Add an explicit terminal `implementation_ready_handoff` route and prohibit routes that start implementation, commit, push, merge, deploy, publish, or contact external systems.
- Retain legacy aliases only as explicit compatibility mappings to one canonical owner; do not let an alias become a competing runner.

## Current Repo Behavior

`command-manifest.yaml:commands` already lists command metadata, but it does not yet represent one integration-neutral lifecycle contract spanning workflow step, adapter, validator, artifact, event, permission, and provenance.

## Target Behavior

- Preserve US1 and FR-028/FR-029: every canonical pre-implementation phase resolves to one owner and one result contract.
- Specialize PL-02 by making route/ownership data machine-validatable before any upstream workflow route is enabled.
- The final route must stop at implementation-ready handoff, never implementation execution.

## Primary Edit Seam

**File:Symbol**: `command-manifest.yaml:commands`.

- Declare the exact workflow adapter, timeout, permission class, allowed mutation scope, deterministic validator, event request, artifact path, version, and provenance for each route.
- Add an explicit no-implementation side-effect policy to the terminal handoff definition.
