# HUD: T013a - Declarative phase adapter contracts

## Objective

Deliver `T013a` so the task scope satisfies: Define declarative phase-adapter contracts in scripts/speckit_workflow_adapter.py for declared inputs, template, output, mutation scope, runner, validator, diagnostics, success event, and side-effect boundary..

## Relevant Domains

- code patterns: make every phase dependency explicit in typed data rather than prompts.
- ops governance: declared mutation/success contracts bound autonomous work.
- resilience: diagnostics and validators are first-class contract fields.

## Candidate Design Slices

- **PL-04 — Implement Pre-Implementation Phase Workflow Adapters.** Define per-phase declarations before registration or execution.

## Proposed Solution

- Create `scripts/speckit_workflow_adapter.py` with immutable `PhaseAdapterContract` data containing phase name, inputs, template/scaffold, output paths, mutation scope, runner, validator, diagnostics, success event, timeout, and allowed effects.
- Define contract factories for `orchestrate -> extract -> scaffold -> LLM Action -> validate -> emit/handoff` without executing them.
- Require every declared output/mutation/event field; reject ambiguous or undeclared effects at construction time.

`scripts/pipeline_driver.py:validate_generated_artifact` and `append_pipeline_success_event` are separate existing seams; the repo has no typed unified phase declaration covering both generation and success conditions.
