# HUD: T009a - Command adapter policy contracts

## Objective

Deliver `T009a` so the task scope satisfies: Define scripts/speckit_command_adapter.py request and reviewed-command policy contracts for allowlisted executable/argv resolution, validated input schema, repository-root cwd, and permission class so any unreviewed effective command is rejected before process creation..

## Relevant Domains

- security: reviewed executable/argv policy must reject untrusted command shapes before process creation.
- code patterns: policy is pure typed validation, separate from execution.
- ops governance: permission class and side-effect scope remain manifest-declared.

## Candidate Design Slices

- **PL-03 — Build Safe Command and Shell Adapter Contract.** This first split defines the reviewed request boundary before T009b can spawn a process.

## Proposed Solution

- Create `scripts/speckit_command_adapter.py` typed request/policy models and `validate_command_request`.
- Accept only manifest-declared executable IDs and argv templates; validate values against per-argument schema; require repository-root cwd; reject dynamic executables, traversal, shell metacharacters, interpolation fragments, and undeclared permission classes.
- Return a structured rejection envelope before calling any subprocess helper.

## Current Repo Behavior

`scripts/pipeline_driver.py:_execute_command` is an existing process-execution seam, while `scripts/hook_pretool_dispatch.py:main` enforces pre-tool denial. Neither is a reusable manifest-bound upstream shell request policy.

## Target Behavior

- Preserve FR-010 and FR-011: every effective shell command is fixed/allowlisted and input-validated before process creation.
- Specialize PL-03: policy resolution yields an immutable reviewed argv request for T009b, never shell text.
- Unreviewed commands fail with a stable reason and no side effect.
