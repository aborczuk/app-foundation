# HUD: T011 - Pipeline command adapter routing

## Objective

Deliver `T011` so the task scope satisfies: Integrate command adapter routing into scripts/pipeline_driver.py or the selected workflow phase adapter without enabling arbitrary shell text..

## Relevant Domains

- build pipeline: connects manifest-declared shell steps to one safe adapter.
- security: prevents generic runner from receiving raw shell text.
- ops governance: preserves declared permission and mutation scope.

## Candidate Design Slices

- **PL-03 — Build Safe Command and Shell Adapter Contract.** Wire the reviewed adapter into phase execution after policy and test seams exist.

## Proposed Solution

- Modify `scripts/pipeline_driver.py:run_step` (or its selected phase-adapter caller) to route only declared upstream `shell` steps through `scripts/speckit_command_adapter.py`.
- Resolve command ID and input data from the T005 manifest; call T009a validation, T009b runner, and T009c envelope sequentially.
- Reject raw command text, undeclared step types, and any request whose permission/mutation scope exceeds the manifest; propagate typed outcome without emitting a success event.

## Current Repo Behavior

`scripts/pipeline_driver.py:run_step` and `_execute_command` are existing execution seams. They are not yet tied to a manifest-reviewed shell adapter contract.

## Target Behavior

- Preserve FR-010, FR-029, and PL-03: all effective shell execution is reviewed and cannot bypass route/permission/side-effect declarations.
- A driver route receives one safe adapter outcome, not direct stdout assumptions.
- Failed/rejected adapter results block phase success and leave event emission to later deterministic gates.
